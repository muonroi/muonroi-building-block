# Muonroi.BuildingBlock.All

> One-package install for the complete Muonroi Building Block commercial stack: rule engine, governance, tenancy, data access, caching, messaging, observability, PDF, and more.

[![NuGet](https://img.shields.io/nuget/v/Muonroi.BuildingBlock.All.svg)](https://www.nuget.org/packages/Muonroi.BuildingBlock.All/)
[![Commercial License](https://img.shields.io/badge/license-Commercial-blue.svg)](https://github.com/muonroi/muonroi-building-block/blob/main/LICENSE-COMMERCIAL)

`Muonroi.BuildingBlock.All` is a metapackage that pulls in every sub-package in the Muonroi Building Block suite in a single `<PackageReference>`. It is the fastest way to bootstrap a new service that needs the full infrastructure stack — rule engine, multi-tenancy, EF Core + Dapper, Redis/in-memory caching, MassTransit messaging, gRPC, SignalR, Hangfire, Quartz, Consul service discovery, OpenTelemetry observability, secrets management, authorization, governance/licensing, and the PDF rendering engine. For production services that should ship only what they use, depend on the individual granular packages instead.

## Installation

```bash
dotnet add package Muonroi.BuildingBlock.All --prerelease
```

> **Commercial license required.** This package sets `<PackageRequireLicenseAcceptance>true</PackageRequireLicenseAcceptance>`. A valid activation proof must be present in deployed environments.

## Quick Start

Because this is a metapackage, there is no registration extension of its own. Each bundled sub-package provides its own `AddXxx` extension. A typical host wiring looks like:

```csharp
// Program.cs — uses capabilities from bundled sub-packages
var builder = WebApplication.CreateBuilder(args);

// Core + tenancy
builder.Services.AddMuonroiCore(builder.Configuration);
builder.Services.AddMuonroiTenancy(builder.Configuration);

// Rule engine
builder.Services.AddRuleEngine<MyContext>();
builder.Services.AddMGeneratedRules();       // generated by Muonroi.RuleEngine.SourceGenerators

// Data access
builder.Services.AddMuonroiEntityFrameworkCore<MyDbContext>(builder.Configuration);
builder.Services.AddMuonroiDapper(builder.Configuration);

// Caching
builder.Services.AddMuonroiRedisCache(builder.Configuration);

// Messaging
builder.Services.AddMuonroiMassTransit(builder.Configuration);

// Observability
builder.Services.AddMuonroiObservability(builder.Configuration);

// Governance / licensing
builder.Services.AddMuonroiGovernance(builder.Configuration);

var app = builder.Build();
app.UseMuonroiTenancy();
app.Run();
```

Each `AddXxx` method and its options type live in the corresponding granular package. The metapackage makes all of them available without separate `<PackageReference>` entries.

## When to Use This Package vs. Granular Packages

| Scenario | Recommendation |
|----------|---------------|
| Greenfield service, want everything available immediately | `Muonroi.BuildingBlock.All` |
| Microservice with a defined bounded context | Individual granular packages — smaller binary, explicit dependency graph |
| OSS-only service (Apache-2.0, no commercial features) | Use the OSS granular packages; do **not** reference this package (it requires a commercial license) |
| Library/NuGet package you are authoring | Individual granular packages only — never take a metapackage dependency in a library |
