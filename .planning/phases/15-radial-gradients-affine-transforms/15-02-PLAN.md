<objective>
Render `radial-gradient(...)` backgrounds as PDF radial shading (ShadingType 3), reusing the Phase 14
axial-shading infrastructure (`BuildStitchingFunction`, the `/Shading` resource plumbing, the
clip+`sh` content-stream pattern). Support circle + ellipse (D-04, ellipse is the CSS default and is
rendered as a unit-circle ShadingType 3 + anisotropic CTM scale), `at center` + keyword positions and
farthest-corner extent (D-05). Widen the `LegacyPrintPolicy` gradient gate to also allow
radial-gradient while keeping conic-gradient and all repeating-* rejected (D-06).

Implements ROADMAP Phase 15 Success Criterion 1 (radial) and contributes to SC3 (no regression /
byte-identical / PerfGate). Depends on Plan 01: shares BoxNode.cs / BoxTreeBuilder.cs /
OwnedPdfWriter.cs / LegacyPrintPolicy.cs / both test files (sequential wave to avoid file conflict).

Purpose: ShadingType 3 is a minimal delta from `BuildAxialShadingDict` - same `/Function`, same
`/Extend`, different `/ShadingType` + 6-value `/Coords`. The ellipse anisotropic `cm` is the only new
content-stream wrinkle, and its clip-ordering is the key pitfall (P3).

Output: `RadialGradient` model + `RadialGradientParser`, `BuildRadialShadingDict`, writer radial
emission, widened gradient gate, and flipped/new policy + render tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied HTML/CSS -> parser/policy | Untrusted `radial-gradient(...)` value strings cross here before layout/writer |
| layout box tree -> PDF writer | RadialGradient (shape/position/stops) flows into ShadingType-3 dict + content-stream `cm`/`sh` |

Offline pure-managed PDF library, no network/auth surface. Realistic threat: malformed/pathological
radial-gradient CSS causing unhandled exceptions, resource exhaustion, NaN/Infinity in PDF numerics,
or a policy bypass that lets conic/repeating reach the writer.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-15.02-01 | Tampering / Elevation | LegacyPrintPolicy gradient gate | mitigate | `isAllowedGradient` allows only linear/radial via explicit `Contains("radial-gradient(")`; keeps `&& !conic-gradient && !repeating-` rejections so conic/repeating cannot bypass to the writer (D-06). Gate runs in both computed-style and inline-style paths (P1, established Phase 14). |
| T-15.02-02 | Denial of Service | RadialGradientParser.TryParse | mitigate | Reuses `MatchParen`/`SplitTopLevel` (bounded, paren-balanced, no catastrophic backtracking); malformed input returns false rather than throwing/looping; stop count guarded (`Stops.Count >= 2` before any shading emission). |
| T-15.02-03 | Tampering | BuildRadialShadingDict numerics | mitigate | Center/radius computed from layout-resolved Rect (finite); radii via Math.Max of finite distances; output formatted with `Num()` (F4, InvariantCulture). Degenerate r=0 still emits a valid /Coords (Extend handles fill). No `Convert.ToDouble`. |
| T-15.02-04 | Tampering | Ellipse clip ordering (P3) | mitigate | Clip `re W n` emitted in page user space BEFORE the anisotropic `cm`, so a hostile/odd shape cannot escape its box clip into the rest of the page. |
| T-15.02-05 | Information Disclosure (SEC-02 invariant) | ShadingType-3 dict | mitigate | `BuildRadialShadingDict` emits only /Shading + /Function dicts - never /JavaScript, /Launch, or /EmbeddedFile; the Phase 5 security invariant is unaffected. |
| T-15.02-06 | Spoofing | n/a (no auth surface) | accept | Offline library; no identity/authn in scope. |
</threat_model>
