  <behavior>
    <!-- Behaviour is asserted as positions in Plan 04; here, encode the algorithm's contract as the design the impl must satisfy. -->
    - Main axis = horizontal for row/row-reverse, vertical for column/column-reverse. Cross axis is the other.
    - flex-basis per item resolved as: explicit FlexBasisRaw length (via ParseLength against the main-axis container size for %); else the item's main-axis size (Width for row, content-measured height for column); else content size measured by laying the item out at the available main size (mirror TableLayoutEngine.MeasureCell using _blockEngine.Layout into a throwaway output).
    - Line breaking: for wrap/wrap-reverse, start a new line when accumulated item main sizes + gaps would exceed the container main size; nowrap = single line.
    - Free-space resolution per line: free = containerMain - sum(basis) - totalMainGaps. If free>0 distribute by flex-grow (frozen-item iteration: items that hit a max are frozen, remaining free re-distributed). If free<0 distribute by flex-shrink scaled by basis (shrink factor = shrink_i*basis_i / Σ(shrink*basis)), clamped at a min size of 0 (or content-min); freeze and re-iterate. flex-grow null→0, flex-shrink null→1.
    - justify-content positions items along the main axis using leftover free space: flex-start (default), flex-end, center, space-between (free/(n-1) between), space-around (free/n, half at ends), space-evenly (free/(n+1) including ends). Gaps are added in addition to justify spacing.
    - Cross axis: each line's cross size = max item cross size on that line. align-items / align-self per item: flex-start, flex-end, center, stretch (item cross size := line cross size when the item has no explicit cross size), baseline (FIRST CUT: treat as flex-start per D-05; document this).
    - align-content (multi-line only) distributes lines along the cross axis: flex-start/flex-end/center/space-between/space-around/stretch (stretch grows each line's cross size to fill remaining cross space).
    - order: items are positioned in ascending Order (null→0), stable for equal order. Visual order only.
    - reverse directions (row-reverse/column-reverse, wrap-reverse) flip the placement direction along the relevant axis.
    - Returns the container's total cross extent (height for row, width-driven height for column) consumed; advances ctx.CurrentY = startY + height (mirror TableLayoutEngine line 136).
  </behavior>

Implement the algorithm per `<behavior>`, deterministically and unit-testably. Concrete structure:
1. Resolve container main size: row→`context.AvailableWidth`; column→use container.Height if explicit (>0) else context-derived. originX = `context.ContentOriginX > 0f ? context.ContentOriginX : context.PageMarginLeftPt`; startY = `context.CurrentY`.
2. Order items: `container.Children.OrderBy(c => c.Order ?? 0)` (stable — use an index tiebreak).
3. Resolve each item's flex-basis (main size) — explicit FlexBasisRaw via a `ResolveBasis` helper that calls ParseLength-equivalent on the raw token (reuse the value already resolved on the box where possible; FlexBasisRaw=="auto"/null→main-axis size or content measure). MEASURE content size by building an item LayoutContext (mirror TableLayoutEngine.CellContext: AvailableWidth = a generous main size, ContentOriginX seeded) and calling `_blockEngine.Layout(item, measureCtx, new List<PositionedElement>(), 0)` to get content height; for row main axis the content main size is the item's natural width (use Width when set, else a measured intrinsic; first cut: explicit Width or basis, fall back to a content-driven estimate via the measure pass).
4. Break into lines (wrap) or one line (nowrap).
5. Per line, resolve flexible lengths with the frozen-item iteration + min(0) clamp.
6. Compute each line's cross size; apply align-content across lines; apply justify-content along main; apply align-items/align-self within each line; honor RowGap/ColumnGap (main-axis gap = ColumnGap for row / RowGap for column; cross-axis gap between lines uses the other).
7. For each item: set its final main/cross position and size (set `item.Width`/`item.Height` for stretch/grow results so the recursive layout honors them — save/restore WidthRaw like TableLayoutEngine line 116-120 to avoid % double-application), build the final item LayoutContext with CurrentY = itemCrossY (row) and ContentOriginX = itemMainX (so nested content renders at the item's X), call `_blockEngine.Layout(item, itemCtx, itemOut, pageIndex)` — THIS recurses through the existing dispatch so nested flex/block/inline/table compose. Then translate itemOut to the item's box if needed and `output.Add(item container PositionedElement)` + `output.AddRange(itemOut)`.
8. Return total cross extent; set `context.CurrentY = startY + totalHeight`.
Handle `IsInlineFlex` as an atomic block first cut (D-05): lay out identically, container participates as a block-level box in its parent (no special inline integration this phase) — add a `// D-05: inline-flex atomic first cut` comment.
