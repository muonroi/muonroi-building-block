  <name>Task 1: Fix AssignColumnIndices bounds guard + colX access</name>
  <files>src/Muonroi.Pdf/Internal/Layout/TableLayoutEngine.cs</files>
  <behavior>
    - A table with 1 row, 40 cells each with colspan=1 but columnCount computed as 36 (due to prior rowspan ghost occupancy) does NOT throw IndexOutOfRangeException.
    - Cells whose column index would exceed columnCount-1 are silently skipped (ColumnIndex clamped to columnCount-1 at minimum, or the cell is excluded from the final rendering pass).
    - The final pass `colX[cell.ColumnIndex]` never accesses beyond colX.Length-1.
  </behavior>
  <action>
  In AssignColumnIndices, after the "while (col < columnCount && occupied[r, col]) col++" loop, add:

    if (col >= columnCount) break;   // cell overflows the declared column grid — skip it

  This is the primary fix per research Gap 6: once col >= columnCount the remaining cells in this
  row have no valid grid slots and should be excluded rather than crashing.

  In the final rendering pass (the "for r / foreach cell" loop that calls colX[cell.ColumnIndex]),
  add a guard before using cell.ColumnIndex:

    if (cell.ColumnIndex < 0 || cell.ColumnIndex >= colX.Length) continue;

  This is defense-in-depth for any ColumnIndex values that slip through (e.g., cells that were
  assigned ColumnIndex=col BEFORE the break — verify the break fires before the assignment, not
  after; if assignment happens first, change the guard to assign only when col < columnCount).

  Do NOT change the method signature, visibility, or the overall two-dimensional array approach.
  Do NOT change the CellWidth helper — it already has Math.Min guard.
  </action>
  <verify>

  </verify>
