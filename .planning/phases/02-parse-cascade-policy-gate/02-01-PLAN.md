  <action>
    Create three exception files in `src/Muonroi.Pdf.Abstractions/Exceptions/` (new directory).

    **PdfException.cs** — abstract base in namespace `Muonroi.Pdf.Abstractions.Exceptions`:
    - `public abstract class PdfException : Exception`
    - Constructor: `protected PdfException(string ruleId, string detail, string message, Exception? inner = null) : base(message, inner)`
    - Properties: `public string RuleId { get; }` and `public string Detail { get; }` set in constructor

    **PdfInputLimitException.cs** — in same namespace:
    - `public sealed class PdfInputLimitException : PdfException`
    - Constructor: `public PdfInputLimitException(string ruleId, string limitName, long actualValue, long limitValue)`
    - Builds message: `$"PDF input limit exceeded: {limitName} = {actualValue}, limit = {limitValue} (rule: {ruleId})"`
    - Properties: `public string LimitName { get; }`, `public long ActualValue { get; }`, `public long LimitValue { get; }` — all set in constructor
    - Sets `Detail` to the same message string, `RuleId` to passed ruleId

    Rule IDs used by the parser (callers must use these exact strings for telemetry consistency):
    - `"limit.max-html-bytes"` — when HTML exceeds `PdfConfigs.PdfLimits.MaxHtmlBytes`
    - `"limit.max-dom-depth"` — when DOM depth exceeds `PdfConfigs.PdfLimits.MaxDomDepth`
    - `"limit.max-element-count"` — when element count exceeds `PdfConfigs.PdfLimits.MaxElementCount`

    **PdfPolicyException.cs** — in same namespace:
    - `public sealed class PdfPolicyException : PdfException`
    - Constructor: `public PdfPolicyException(IReadOnlyList<PolicyViolation> violations)`
    - Builds message: `$"PDF policy validation failed with {violations.Count} violation(s): {violations[0].RuleId}"` (safe — caller must pass non-empty list)
    - Property: `public IReadOnlyList<PolicyViolation> Violations { get; }` — set in constructor
    - Sets `RuleId` to `violations[0].RuleId`, `Detail` to joined rule IDs

    All three classes: no XML doc comments needed (no CS1591 requirement in Phase 2 for new exception types in the Exceptions folder — they are internal API types, not the public rendering contracts).
