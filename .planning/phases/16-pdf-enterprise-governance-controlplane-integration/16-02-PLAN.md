<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| render call → metering hook | A throwing metering path must not become a denial-of-service on the OSS render |
| tenant context → quota record | TenantId must be the caller's own tenant; cross-tenant attribution would leak/misbill usage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-05 | Denial of Service | metering hook throwing and blocking render | mitigate | `RecordMeteringAsync` wraps `IncrementUsageAsync` in try/catch, logs via `IMLog`, swallows; render returns the inner result regardless. Test 2 asserts a throwing tracker does not fail the render. |
| T-16-06 | Information disclosure / Spoofing | cross-tenant quota attribution | mitigate | Tenant resolved only from `ISystemExecutionContextAccessor.CurrentContext.TenantId` / `TenantContext.CurrentTenantId` (ambient, server-set) — never a caller-supplied string; mirrors `EnterpriseLicenseGuardEnhancer`. |
| T-16-07 | Repudiation | attacker suppresses metering | accept | D-02 is record-only billing/analytics, not a security control; suppression is non-blocking and logged. Independent audit trail (D-03) is unaffected. Low value, no PII. |
| T-16-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan. |
</threat_model>
