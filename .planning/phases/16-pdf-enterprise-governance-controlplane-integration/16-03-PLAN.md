<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| audit store → compliance evidence pack | Audit records cross into a tenant-facing compliance export; cross-tenant leakage would expose another tenant's publish history |
| async EF query → sync Load() | The sync bridge must not deadlock or hide query failures |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-08 | Information disclosure | cross-tenant audit leakage in evidence pack | mitigate | The adapter surfaces only `pdf.template.*` records from `IRuleSetAuditStore`; tenant scoping is enforced upstream by the same governance compliance export path that already scopes ruleset audit. The adapter adds no new cross-tenant query (no tenant filter widening). Verify `QueryAsync` honors the existing tenant context. |
| T-16-09 | Repudiation / Tampering | dropped or altered audit records | mitigate | Field mapping preserves `ContentHash` and `Signature` from the source entry; the evidence pack re-chains via the existing HMAC machinery (Don't Hand-Roll). No mutation of source events. |
| T-16-10 | Denial of Service | sync bridge failure crashing compliance export | mitigate | `Load()` try/catch logs and returns an empty registry on `QueryAsync` failure; the export degrades gracefully rather than throwing (No Silent Catch). |
| T-16-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan. |
</threat_model>
