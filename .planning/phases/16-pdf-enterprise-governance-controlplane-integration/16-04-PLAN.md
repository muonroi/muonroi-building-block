<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client multipart PNG → SSIM score | Caller-supplied images cross into the rollback decision; a caller could submit images to force/avoid rollback |
| caller-supplied rolloutId → rollback action | A rollout id triggers a state-changing rollback |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-16-11 | Tampering | SSIM score manipulation to bypass/force rollback | mitigate | Score is computed server-side by `SsimScorer.Compare` from the supplied bytes; the caller cannot inject a fake score. Submitting manipulated images is the canary's own input under test — deterministic SSIM math is the intended gate. |
| T-16-12 | Elevation of privilege / Tampering | unauthorized rollback via forged rolloutId | mitigate | The `/api/canary/pdf/score` endpoint inherits the existing control-plane auth on the canary route group; `rolloutId` is parsed as a `Guid?` (V5 input validation) and rollback only fires when SSIM is genuinely sub-threshold. Rollback itself is audited by `CanaryRolloutService` (actor="system"). |
| T-16-13 | Denial of Service | spurious rollback from a transient bad render | accept | Single-shot SSIM gate is the Phase 9 design; multi-sample debounce is out of scope. Rollback is reversible by operators; reason string records the triggering SSIM. |
| T-16-SC | Tampering | npm/pip/cargo installs | mitigate | No package installs in this plan. |
</threat_model>
