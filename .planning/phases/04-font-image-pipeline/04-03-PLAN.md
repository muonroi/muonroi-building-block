**DataUriDecoder** (`src/Muonroi.Pdf/Internal/Image/DataUriDecoder.cs`):
- Namespace: `Muonroi.Pdf.Internal.Image`
- `internal static class DataUriDecoder`
- Method: `internal static (ReadOnlyMemory<byte> Bytes, string ContentType) Decode(string dataUri)`

Implementation:
1. Strip `"data:"` prefix (verify starts with `"data:"` case-sensitive; throw `PdfException("IMG-FORMAT", "Not a data: URI")` if not)
2. Find first comma with `int commaIdx = rest.IndexOf(',')` — throw `PdfException("IMG-FORMAT", "data: URI missing comma separator")` if < 0
3. Split `header = rest[..commaIdx]` and `dataStr = rest[(commaIdx+1)..]`
4. `bool isBase64 = header.EndsWith(";base64", StringComparison.OrdinalIgnoreCase)`
5. `string mediaType = isBase64 ? header[..^";base64".Length] : header`
6. If `mediaType` is empty → `"text/plain;charset=US-ASCII"` (RFC 2397 default)
7. `string contentType = mediaType.Split(';')[0].Trim()` — strip parameters
8. If `contentType` is empty → `"text/plain"`
9. Validate for image types: if `contentType.StartsWith("image/", StringComparison.OrdinalIgnoreCase)` and `!isBase64` → throw `PdfException("IMG-FORMAT", "data: URI image payload must be base64-encoded")`
10. Decode: strip whitespace from `dataStr` (`dataStr.Replace("\r","").Replace("\n","").Replace(" ","")`) then `Convert.FromBase64String(dataStr)` — catch `FormatException` and rethrow as `PdfException("IMG-FORMAT", "Invalid base64 in data: URI")`
11. Return `(new ReadOnlyMemory<byte>(bytes), contentType)`

**PureImageDecoder** (`src/Muonroi.Pdf/Internal/Image/PureImageDecoder.cs`):
- Namespace: `Muonroi.Pdf.Internal.Image`
- `internal sealed class PureImageDecoder : IImageDecoder`
- No constructor dependencies
- Method: `public DecodedImage Decode(ReadOnlySpan<byte> data, string contentType)`

PNG path (triggered when magic bytes match OR contentType is "image/png"):
1. Check length: `if (data.Length < 24) throw PdfException("IMG-FORMAT", "PNG data too short to contain IHDR")`
2. Validate magic: bytes 0-7 must equal `{ 0x89, 0x50, 0x4E, 0x47, 0x0D, 0x0A, 0x1A, 0x0A }` — throw `PdfException("IMG-FORMAT", "Invalid PNG magic bytes")` on mismatch
3. `int width  = (int)BinaryPrimitives.ReadUInt32BigEndian(data.Slice(16, 4))`
4. `int height = (int)BinaryPrimitives.ReadUInt32BigEndian(data.Slice(20, 4))`
5. Return `new DecodedImage(width, height, data.ToArray(), "image/png")`

JPEG path (triggered when magic matches FF D8 OR contentType is "image/jpeg" or "image/jpg"):
1. Check length: `if (data.Length < 4) throw PdfException("IMG-FORMAT", "JPEG data too short")`
2. Validate SOI: `if (data[0] != 0xFF || data[1] != 0xD8) throw PdfException("IMG-FORMAT", "Invalid JPEG SOI marker")`
3. Scan forward from `pos = 2`:
   - Read `byte markerByte = data[pos + 1]` (after verifying `data[pos] == 0xFF`)
   - If `markerByte == 0xFF` (padding): advance `pos++; continue`
   - If `markerByte` is `0xC0, 0xC1, 0xC2, or 0xC3` (SOF0-SOF3):
     - Validate `pos + 9 <= data.Length` — throw if truncated
     - `int height = BinaryPrimitives.ReadUInt16BigEndian(data.Slice(pos + 5, 2))`
     - `int width  = BinaryPrimitives.ReadUInt16BigEndian(data.Slice(pos + 7, 2))`
     - Return `new DecodedImage(width, height, data.ToArray(), "image/jpeg")`
   - Otherwise: skip segment — `int segLen = BinaryPrimitives.ReadUInt16BigEndian(data.Slice(pos + 2, 2)); pos += 2 + segLen`
   - Guard: `if (pos + 3 >= data.Length) throw PdfException("IMG-FORMAT", "JPEG SOF marker not found")`
4. After loop: throw `PdfException("IMG-FORMAT", "JPEG SOF marker not found")`

Auto-detect by magic bytes (called first, before content-type branching):
- Check first 2 bytes: if `data[0] == 0xFF && data[1] == 0xD8` → JPEG path
- Check first 8 bytes for PNG magic → PNG path
- If neither matches: throw `PdfException("IMG-FORMAT", $"Unrecognized image format (magic: {data[0]:X2} {data[1]:X2})")`

Required using: `System.Buffers.Binary` for `BinaryPrimitives`. Also need `using Muonroi.Pdf.Abstractions.Exceptions;` for `PdfException`.

Note: Check if `PdfException` has a two-arg constructor `(string code, string message)`. If not, use the available constructor from `PdfException.cs`. Read the file first.

Create `src/Muonroi.Pdf/Internal/Image/ImagePipeline.cs`:
- Namespace: `Muonroi.Pdf.Internal.Image`
- `internal sealed class ImagePipeline`
- No constructor dependencies (resolver and decoder are method parameters — not injected — to keep the class stateless)

Method:
```
internal async Task<IReadOnlyDictionary<string, DecodedImage>> ResolveAsync(
    IStyledDocument doc,
    IResourceResolver resolver,
    IImageDecoder decoder,
    PdfConfigs.PdfLimits limits,
    CancellationToken ct)
```

Implementation:
1. Collect all img src values: call private `CollectImageSrcs(doc.Root)` which recursively walks `IStyledNode` tree
   - `if (node.IsElement && node.LocalName == "img") { string? src = node.GetAttribute("src"); if (!string.IsNullOrEmpty(src)) yield return src; }`
   - Recurse into `node.Children`
   - Deduplicate with `Distinct()` (StringComparer.Ordinal)

2. For each unique src value:
   a. `ct.ThrowIfCancellationRequested()`
   b. If `src.StartsWith("data:", StringComparison.OrdinalIgnoreCase)`:
      - `(ReadOnlyMemory<byte> bytes, string contentType) = DataUriDecoder.Decode(src)`
      - `DecodedImage decoded = decoder.Decode(bytes.Span, contentType)`
   c. Else (external URI):
      - `Uri uri = new Uri(src, UriKind.Absolute)` — catch `UriFormatException` and log at debug level then skip (image not available)
      - `ResourceResult? result = await resolver.ResolveAsync(uri, contentTypeHint: null, ct).ConfigureAwait(false)`
      - If `result == null` → log debug "Image not resolved: {src}"; skip (do not add to dictionary)
      - `DecodedImage decoded = decoder.Decode(result.Bytes.Span, result.ContentType)`
   d. Validate pixel count: `if ((long)decoded.Width * decoded.Height > limits.MaxImagePixels)` → throw `new PdfInputLimitException("IMG-MAX-PIXELS", "MaxImagePixels", (long)decoded.Width * decoded.Height, limits.MaxImagePixels)`
   e. Add `dict[src] = decoded`

3. Return `dict` as `IReadOnlyDictionary<string, DecodedImage>`

Security requirements:
- `ImagePipeline` has NO constructor injection of `HttpClient`, `IHttpClientFactory`, `FileStream`, or any file system abstraction
- The ONLY way to get external image bytes is through the `resolver` parameter (IResourceResolver)
- `file://` URIs: let `IResourceResolver` handle the rejection — the pipeline itself does not filter by scheme (the default resolver implementation rejects file:// per SEC-06)

Logging: The class needs NO logger — use `System.Diagnostics.Debug.WriteLine` for skipped images to avoid introducing IMLog dependency in this internal class. (IMLog wiring happens in Phase 6 DI.)

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTML img src → ImagePipeline | Untrusted URI string from parsed HTML; could be SSRF attempt |
| data: URI content → DataUriDecoder | Untrusted base64 payload from HTML attribute |
| IResourceResolver bytes → PureImageDecoder | Bytes from resolver — could be malformed PNG/JPEG |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-03-01 | Information Disclosure | `ImagePipeline` making outbound network calls | mitigate | `ImagePipeline` has no `HttpClient` or file system dep; all external bytes come via `IResourceResolver` bytes-only contract; engine never calls DNS or opens sockets |
| T-04-03-02 | Spoofing | data: URI with wrong content-type header (e.g., `data:text/plain;base64,<png-bytes>`) | mitigate | `PureImageDecoder` validates magic bytes regardless of declared content type — auto-detect runs first before content-type branching |
| T-04-03-03 | DoS | MaxImagePixels check skipped for data: URIs | mitigate | MaxImagePixels validation runs after decode regardless of source (data: URI or external resolver) |
| T-04-03-04 | Tampering | Malformed PNG/JPEG bytes causing OOB read in PureImageDecoder | mitigate | Length guards before every `Slice()` call; throws `PdfException` on truncated data rather than reading beyond bounds |
</threat_model>
