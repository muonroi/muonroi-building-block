**PositionedPageList.cs:**
Add two `init`-settable properties (use C# 9 init accessors; Muonroi.Pdf targets net8.0 so this is available):
- `public IReadOnlyList<EmbeddedFontInfo> EmbeddedFonts { get; init; } = [];`

Required usings: `Muonroi.Pdf.Internal.Font` (for `EmbeddedFontInfo`) and `Muonroi.Pdf.Abstractions.Engine` (for `DecodedImage`).

Note: `IPositionedPageList` in Abstractions does NOT need to expose these properties — they are internal implementation details consumed within the same assembly by Phase 5's `PdfSharpCoreWriter`.

---

**BoxTreeBuilder.cs:**
1. Add optional parameter to `Build`: change signature to:
   `public BlockBox Build(IStyledNode root, IReadOnlyDictionary<string, DecodedImage>? resolvedImages = null)`
   Store as field: `private IReadOnlyDictionary<string, DecodedImage>? _resolvedImages;`
   At the start of `Build`, set `_resolvedImages = resolvedImages`.

   WARNING: `BoxTreeBuilder` is not thread-safe (uses field state). This is acceptable — one instance per render call.

2. In `CreateBox`: when the element is `<img>` (i.e., the computed display maps to a `BlockBox` or inline and `node.LocalName == "img"`), create a `ReplacedBox` instead of the default. Add this check in `CreateBox` before the `display` switch:
   - `if (string.Equals(node.LocalName, "img", StringComparison.OrdinalIgnoreCase))`:
     - Return `new ReplacedBox { Source = node, Src = node.GetAttribute("src") }`
   (CSS display value determines position in flow but img elements always produce ReplacedBox)

3. In `ResolveCssProperties`: add a branch for `ReplacedBox`:
   - `if (box is ReplacedBox replaced && replaced.Src != null && _resolvedImages != null)`:
     - `if (_resolvedImages.TryGetValue(replaced.Src, out DecodedImage? decoded))`:
       - `replaced.NaturalWidth = decoded.Width * Units.PxToPt`  — convert px to pt for layout units
       - `replaced.NaturalHeight = decoded.Height * Units.PxToPt`
   - If CSS `width`/`height` are set on the img element, those override NaturalWidth/Height (already handled by the existing `box.Width` / `box.Height` parsing)

Required usings: `Muonroi.Pdf.Abstractions.Engine` (for `DecodedImage`), `Muonroi.Pdf.Internal.Layout.Boxes` already imported.

Add a new async `Layout` overload to `LayoutEngine`. Do NOT modify the existing synchronous `Layout` signature — it must remain for Phase 3 test compatibility.

New method:
```
public async Task<IPositionedPageList> LayoutAsync(
    IStyledDocument doc,
    PdfRenderOptions options,
    PdfConfigs.PdfLimits limits,
    IFontResolver? fontResolver,
    IResourceResolver? imageResolver,
    IImageDecoder imageDecoder,
    CancellationToken ct)
```

Implementation:
1. **Font pre-pass** (if `fontResolver != null`):
   - `var fontPipeline = new FontPipeline()`
   - `(SixLaborsTextMetrics metrics, IReadOnlyDictionary<string, ReadOnlyMemory<byte>> fontBytesMap) = await fontPipeline.ResolveAsync(doc, fontResolver, limits, ct).ConfigureAwait(false)`
   - Replace `_textMetrics` for this render — BUT `_textMetrics` is readonly in the current design. Instead: construct a temporary `LayoutEngine` with real metrics: `var engineWithRealMetrics = new LayoutEngine(metrics)`. Use this local variable for the layout steps.
   - Store `fontBytesMap` for post-layout use

2. **Image pre-pass** (if `imageResolver != null`):
   - `var imagePipeline = new ImagePipeline()`
   - `IReadOnlyDictionary<string, DecodedImage> resolvedImages = await imagePipeline.ResolveAsync(doc, imageResolver, imageDecoder, limits, ct).ConfigureAwait(false)`
   - If `imageResolver == null`: `resolvedImages = new Dictionary<string, DecodedImage>()`

3. **Two-pass layout** using the engine with real metrics (or `this` if fontResolver was null):
   - `ILayoutEngine engine = fontResolver != null ? engineWithRealMetrics : this` — use `LayoutEngine` directly (no interface needed; just use the local variable pattern)
   - Pass `resolvedImages` to `RunLayout` — update `RunLayout` signature to accept `IReadOnlyDictionary<string, DecodedImage>? resolvedImages` and forward to `BoxTreeBuilder.Build(doc.Root, resolvedImages)`
   - Run pass 1 (totalPages=0), check MaxPages, run pass 2 (totalPages=pass1.PageCount)

4. **Post-layout: glyph collection + subsetting** (only if fontResolver != null and fontBytesMap has entries):
   - `var collector = new GlyphCollector()`
   - `IReadOnlyDictionary<string, IReadOnlySet<int>> usedCodepoints = collector.Collect(pass2Result, fontCollection)`
   - Wait — `fontCollection` was built inside `FontPipeline`; it needs to be returned from `FontPipeline.ResolveAsync`
   - UPDATE: Change `FontPipeline.ResolveAsync` return type to include `FontCollection` as third tuple element: `(SixLaborsTextMetrics TextMetrics, IReadOnlyDictionary<string, ReadOnlyMemory<byte>> FontBytesMap, FontCollection Collection)` — if FontPipeline was already written with the 2-tuple, extend it here
   - For each font family in `fontBytesMap`:
     - `IReadOnlySet<int> codepoints = usedCodepoints.TryGetValue(family, out var cp) ? cp : new HashSet<int>()`
     - `var subsetter = new TrueTypeFontSubsetter()`
     - `ReadOnlyMemory<byte> subsetBytes = subsetter.Subset(fontBytesMap[family], codepoints)`
     - Get `FontFaceDeclaration decl = doc.FontFaces.First(f => f.Family == family)` (or use separate map)
     - Build `EmbeddedFontInfo info = new(decl.Family, decl.Weight, decl.Style, subsetBytes, codepoints)`
     - Add to `List<EmbeddedFontInfo> embeddedFonts`

5. Return the final `PositionedPageList` with properties set:
   ```csharp
   var finalResult = (PositionedPageList)pass2Result;
   return finalResult with {
       EmbeddedFonts = embeddedFonts,
       Images = resolvedImages
   };
   ```
   This requires `PositionedPageList` to support `with` (it's a class, not a record — use property setters or init; since we added `init` in Task 1, we cannot use `with` directly on a class). Instead: create a new `PositionedPageList` and copy pages — OR change the approach:
   
   **Simpler approach**: After Task 1 adds `EmbeddedFonts` and `Images` as `init` properties, the `PositionedPageList` is created inside `RunLayout`. We cannot easily set `init` after construction. Therefore: add TWO mutable internal setters to `PositionedPageList`:
   - Change `init` to a regular `set` (internal) for `EmbeddedFonts` and `Images` — these are internal properties not exposed through `IPositionedPageList`
   - Then in `LayoutEngine.LayoutAsync`: after `pass2Result` is returned (as `PositionedPageList`), cast to `PositionedPageList` and set `EmbeddedFonts` and `Images` properties directly

   This is the correct approach — `PositionedPageList` is `internal sealed`, so adding internal setters does not break any public API.

Required usings in LayoutEngine: `Muonroi.Pdf.Internal.Font`, `Muonroi.Pdf.Internal.Image`, `SixLabors.Fonts`.

Note on `FontPipeline` return type update: In Plan 04-04, `FontPipeline.ResolveAsync` was specified to return `(SixLaborsTextMetrics, IReadOnlyDictionary<string, ReadOnlyMemory<byte>>)`. This plan extends it to also return the `FontCollection`. Either edit `FontPipeline.cs` directly here to add the third tuple element, or read the file to confirm its current return type and adjust accordingly. The executor should read `FontPipeline.cs` before editing to avoid conflicts.
