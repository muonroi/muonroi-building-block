## LayoutEngine Design

Namespace: `Muonroi.Pdf.Internal.Layout`

```csharp
// src/Muonroi.Pdf/Internal/Layout/LayoutEngine.cs
// Per CONTEXT.md Decision 4 (locked) — two-pass for counter(pages)
internal sealed class LayoutEngine
{
    private readonly BoxTreeBuilder _treeBuilder;
    private readonly BlockLayoutEngine _blockEngine;
    private readonly InlineLayoutEngine _inlineEngine;
    private readonly TableLayoutEngine _tableEngine;
    private readonly PaginationEngine _paginationEngine;

    public LayoutEngine()
    {
        _treeBuilder = new BoxTreeBuilder();
        _inlineEngine = new InlineLayoutEngine();
        _blockEngine = new BlockLayoutEngine(_inlineEngine);
        _tableEngine = new TableLayoutEngine(_blockEngine, _inlineEngine);
        _paginationEngine = new PaginationEngine();
    }

    public IPositionedPageList Layout(
        IStyledDocument doc,
        PdfRenderOptions options,
        PdfConfigs.Limits limits,
        CancellationToken ct = default)
    {
        // Pass 1: layout with totalPages = 0
        var pass1 = RunLayout(doc, options, limits, totalPages: 0, ct);

        // MaxPages enforcement — after pass 1, before pass 2 (CONTEXT.md Decision 9)
        if (pass1.PageCount > limits.MaxPages)
            throw new PdfInputLimitException(
                $"Document produces {pass1.PageCount} pages which exceeds the configured limit of {limits.MaxPages}.");

        ct.ThrowIfCancellationRequested();

        // Pass 2: layout with resolved total page count
        return RunLayout(doc, options, limits, totalPages: pass1.PageCount, ct);
    }

    private PositionedPageList RunLayout(
        IStyledDocument doc,
        PdfRenderOptions options,
        PdfConfigs.Limits limits,
        int totalPages,
        CancellationToken ct)
    {
        // Build box tree from styled DOM
        var rootBox = _treeBuilder.Build(doc.Root);

        // Initialize layout context
        var (pageWidthPt, pageHeightPt) = GetPageDimensions(options);
        var pageRule = doc.PageRule;
        var margins = ResolveMargins(pageRule, options);

        var context = new LayoutContext
        {
            PageWidth = pageWidthPt - margins.Left * Units.MmToPt - margins.Right * Units.MmToPt,
            PageHeight = pageHeightPt - margins.Top * Units.MmToPt - margins.Bottom * Units.MmToPt,
            AvailableWidth = pageWidthPt - margins.Left * Units.MmToPt - margins.Right * Units.MmToPt,
            CurrentY = 0f,
            CurrentPageIndex = 0,
            TotalPages = totalPages,
            PageMargins = margins,
        };

        // Layout all content as a single pass (unbounded in Y)
        var flatElements = new List<PositionedElement>();
        _blockEngine.Layout(rootBox, context, flatElements, pageIndex: 0);

        ct.ThrowIfCancellationRequested();

        // Paginate: split flat elements into pages, add header/footer, resolve counters
        return _paginationEngine.Paginate(flatElements, pageRule, options, context, rootBox);
    }

    private static (float Width, float Height) GetPageDimensions(PdfRenderOptions options)
    {
        var (w, h) = PdfPageSizeDimensions.Get(options.PageSize);
        return options.Orientation == PdfOrientation.Landscape ? (h, w) : (w, h);
    }

    private static PdfMargins ResolveMargins(IPageRule? pageRule, PdfRenderOptions options)
    {
        // CONTEXT.md Decision 3 precedence:
        // 1. PdfRenderOptions.Margins if non-default
        // 2. CSS @page margins
        // 3. Default 10mm
        var defaultMargins = PdfMargins.Default10mm;
        bool optionsOverride = options.Margins.Top != defaultMargins.Top
            || options.Margins.Right != defaultMargins.Right
            || options.Margins.Bottom != defaultMargins.Bottom
            || options.Margins.Left != defaultMargins.Left;

        if (optionsOverride) return options.Margins;
        if (pageRule is not null) return pageRule.Margins;
        return defaultMargins;
    }
}
```

## BlockLayoutEngine Update

BlockLayoutEngine in Plan 05 has a placeholder `LayoutTable` method. Now that TableLayoutEngine exists (Plan 06), replace the placeholder:
- BlockLayoutEngine's DispatchLayout must call `_tableEngine.Layout(tableBox, context, output, pageIndex)` when the box is a TableBox.
- This requires BlockLayoutEngine to receive a TableLayoutEngine in its constructor (or via a property). The simplest approach: add a `TableLayoutEngine? _tableEngine` field to BlockLayoutEngine and a setter, then LayoutEngine sets it after constructing both.

OR: LayoutEngine.RunLayout handles table dispatch directly in its orchestration. After _blockEngine.Layout, post-process elements... this becomes complex.

RECOMMENDED APPROACH: Since LayoutEngine creates all engines, have LayoutEngine pass a dispatch callback to BlockLayoutEngine. Simple implementation:
- BlockLayoutEngine constructor accepts an optional `Func<TableBox, LayoutContext, List<PositionedElement>, int, float>? tableLayoutFunc`
- In LayoutEngine constructor: after creating tableEngine, set `_blockEngine.TableLayoutFunc = _tableEngine.Layout`
- In BlockLayoutEngine.DispatchLayout: `if (box is TableBox tb && _tableLayoutFunc != null) return _tableLayoutFunc(tb, ctx, out, page);`

This avoids circular dependency and keeps construction simple.

## KNOWN-DEVIATIONS.md

Create at the repo root `KNOWN-DEVIATIONS.md` (or check if it already exists). Document exactly these Phase 3 deviations:

```markdown
# Known CSS 2.1 Deviations

This file documents intentional deviations from the CSS 2.1 specification in the Muonroi.Pdf layout engine.

## Phase 3: Box Tree + Layout Engine

### KD-03-01: `@page { size: ... }` ignored
**CSS 2.1:** `@page { size: A5 landscape; }` overrides the output page dimensions.
**Muonroi.Pdf v0.1:** The `size` property in `@page` rules is parsed but IGNORED. Page dimensions are always taken from `PdfRenderOptions.PageSize` and `PdfRenderOptions.Orientation`.
**Workaround:** Set `PdfRenderOptions.PageSize = PdfPageSize.A5` and `Orientation = Landscape` in code.
**Target fix:** v0.2 (post Phase 7).

### KD-03-02: Orphans and widows not enforced
**CSS 2.1:** `orphans` and `widows` properties control minimum lines at page breaks.
**Muonroi.Pdf v0.1:** `orphans` and `widows` properties are recognized but have no effect. Page breaks are determined by content height only.
**Workaround:** Use `page-break-inside: avoid` on the containing element.
**Target fix:** Not planned for v0.1.

### KD-03-03: Two-pass counter boundary shift
**CSS 2.1:** `counter(pages)` should resolve to the total number of pages.
**Muonroi.Pdf v0.1:** Two-pass layout is used. If substituting the correct `counter(pages)` value in pass 2 causes a line reflow that shifts a page boundary (e.g., "Page 1 of 10" is wider than "Page 1 of 0"), the pass 2 result may show one more page than the value displayed. A third pass is not performed. The pass-2 result is always authoritative.
**Impact:** Only affects documents where the total page count has more digits than the placeholder value in pass 1 (e.g., total pages crosses 10). Rare in practice.
**Target fix:** Not planned for v0.1.

### KD-03-04: `counter(page)` and `counter(pages)` inside header/footer HTML not resolved
**CSS 2.1:** CSS counters in generated content inside `@page` margin boxes should resolve correctly.
**Muonroi.Pdf v0.1:** Counter substitution applies only to InlineBox TextContent in the document body. Counter expressions in `IPageRule.TopMarginBoxHtml` and `BottomMarginBoxHtml` are NOT substituted. Use `PdfRenderOptions.Header.Html` with the counter resolved externally, or use a template placeholder.
**Target fix:** v0.2.
```
