`public static IServiceCollection AddPdf(this IServiceCollection services, IConfiguration configuration)`:

1. Options validation (DI-03, SC5):
```
services
    .AddOptions<PdfConfigs>()
    .BindConfiguration(PdfConfigs.SectionName)
    .Validate(cfg =>
        cfg.Limits.MaxHtmlBytes > 0 &&
        cfg.Limits.MaxDomDepth > 0 &&
        cfg.Limits.MaxElementCount > 0 &&
        cfg.Limits.MaxImagePixels > 0 &&
        cfg.Limits.MaxPages > 0 &&
        cfg.Limits.MaxRenderDurationMs > 0 &&
        cfg.Limits.MaxFontFiles > 0,
        "PdfConfigs: all limits must be positive integers")
    .ValidateOnStart();
```
NOTE on the const-vs-instance caveat (RESEARCH Pitfall 3): `PdfConfigs.PdfLimits` exposes its defaults as `const`, but the bound `cfg.Limits` is an instance whose properties take their values from configuration. The `cfg.Limits.*` references in the lambda must read instance members. If `PdfLimits` has ONLY `const` members and no settable instance properties, the binding cannot override them and `MaxPages: 0` from config would never bind — in that case the validation lambda will not see the 0. Verify `PdfConfigs.PdfLimits` actually has instance get/set properties before relying on this; if it is const-only, surface a BLOCKING note in the SUMMARY because SC5 cannot be satisfied without settable instance properties. (Do not modify PdfConfigs here — that is an Abstractions change; flag it for a gap-closure plan.)

2. Default registrations (DI-02, DI-04 — all `TryAddSingleton` so a second `AddPdf` call or caller override is a no-op):
```
services.TryAddSingleton<IHtmlParser, AngleSharpHtmlParser>();
services.TryAddSingleton<ICssCascadeEngine, AngleSharpCascadeEngine>();
services.TryAddSingleton<IPdfCssPolicy, DefaultStrictPolicy>();
services.TryAddSingleton<IImageDecoder, PureImageDecoder>();
services.TryAddSingleton<IResourceResolver, ThrowingResourceResolver>();
services.TryAddSingleton<IPdfWriter, PdfSharpCoreWriter>();
services.TryAddSingleton<IMPdfService, MPdfService>();
// No registration for IFontResolver (Decision 7) — caller supplies it; MPdfService's optional ctor param resolves to null.
```
Verify each default type's constructor is parameterless or DI-resolvable. If `AngleSharpHtmlParser`/`AngleSharpCascadeEngine`/`DefaultStrictPolicy` need constructor args (e.g. limits/options), register with a factory lambda that resolves them; do not assume parameterless.

3. Telemetry descriptor registration (TEL-01):
```
services.TryAddEnumerable(ServiceDescriptor.Singleton<ITelemetryDescriptor, PdfTelemetryDescriptor>());
```
This makes `PdfTelemetryDescriptor` resolvable by OtelSetup. Use `TryAddEnumerable` (not `TryAddSingleton`) so it coexists with other packages' descriptors in the `IEnumerable<ITelemetryDescriptor>` collection.

4. `return services;`

If `MPdfService`'s constructor takes `IFontResolver?` with a default of null, the container will inject null when unregistered — confirm the container resolves the optional dependency. If the DI container cannot bind an optional `IFontResolver?` parameter, register `MPdfService` with an explicit factory: `services.TryAddSingleton<IMPdfService>(sp => new MPdfService(sp.GetRequiredService<IHtmlParser>(), ..., sp.GetService<IFontResolver>()));`. Prefer the factory form to guarantee the null-fallback path works.
