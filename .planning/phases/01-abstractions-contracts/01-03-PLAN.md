## Muonroi.Pdf.Enterprise stub requirements (PKG-04)

The Enterprise stub is an empty project — no .cs files, no code. Its purpose:
1. Lock the `Muonroi.Pdf.Enterprise` namespace so no other package can claim it
2. Set `IsCommercialPackage=true` so CI (via `pre-publish-gate.ps1`) applies the commercial license auto-pack
3. Establish the assembly hash pipeline entry point for `InjectAssemblyHash.ps1`

The stub ships with v0.1 GA (Phase 7) with an empty assembly — no types inside.

## Directory structure

```
src/
├── Muonroi.Pdf.Abstractions/     ← exists (modified in Wave 1)
│   └── Muonroi.Pdf.Abstractions.csproj
└── Muonroi.Pdf.Enterprise/       ← NEW (create directory + csproj)
    └── Muonroi.Pdf.Enterprise.csproj
```

## Existing csproj pattern to follow

Look at `src/Muonroi.Pdf.Abstractions/Muonroi.Pdf.Abstractions.csproj` (post Wave 1) as a reference for PropertyGroup structure. The Enterprise project differs in:
- `TargetFramework` = `net8.0` (NOT netstandard2.0 — Enterprise is runtime-only)
- `IsCommercialPackage` = `true` (new property, does not exist in Abstractions)
- No `ProjectReference` entries
- No `PackageReference` entries
- No source files — the assembly is intentionally empty

## How IsCommercialPackage is used

`IsCommercialPackage` is a custom MSBuild property read by `scripts/pre-publish-gate.ps1` and `scripts/InjectAssemblyHash.ps1`. The csproj declares it; scripts read it via `$(IsCommercialPackage)`. No additional SDK support is needed — it is a plain boolean property.

## Directory.Build.props

The repo has a `Directory.Build.props` at the solution root that provides `VersionPrefix`, `VersionSuffix`, `ImplicitUsings`, `Nullable`, and other shared properties to all projects. The Enterprise csproj does not need to re-declare any of these — they are inherited automatically.

## Build verification commands

After creating the stub, run builds in order:
1. `dotnet build src/Muonroi.Pdf.Abstractions/Muonroi.Pdf.Abstractions.csproj`
   - Expected: Build succeeded, 0 Error(s)
   - Confirms: TFM switch, GlobalUsings fix, Engine/ seams, PdfConfigs, PdfTelemetryNames all compile on netstandard2.0

2. `dotnet build src/Muonroi.Pdf.Enterprise/Muonroi.Pdf.Enterprise.csproj`
   - Expected: Build succeeded, 0 Error(s)
   - Confirms: Empty stub compiles on net8.0

If a build fails, read the full error output before attempting fixes. Common failure modes:
- `CS8933` or missing type after TFM change: a using in GlobalUsings.cs references a type not in netstandard2.0 BCL
- `NETSDK1138`: a ProjectReference targets a framework incompatible with the parent — ensure no ProjectReference remains in Abstractions csproj
- `NU1102`: package version not found — check Directory.Packages.props for correct AngleSharp.Css pin
