# Phase 8.5 — Owned PDF Writer: Summary

## Overview

Productionized the `OwnedPdfWriter` spike into a fully-featured pure-managed PDF 1.7 writer,
removing the PdfSharpCore dependency from the default render path. All 7 plans executed
sequentially; 5 atomic commits on branch `phase/08.5-owned-pdf-writer`.

---

## Per-Plan Results

### Plan 01 — FontSubsetResult + OldToNewGid/SortedGids (COMPLETE)

**Result:** Green. `FontSubsetResult` record introduced in `TrueTypeFontSubsetter.cs`.
`TrueTypeFontSubsetter.Subset` (and the private `BuildSubsetFont`) now return `FontSubsetResult`
instead of `ReadOnlyMemory<byte>`. `EmbeddedFontInfo` carries `OldToNewGid` and `SortedGids`
with a 5-arg backward-compat constructor for test helpers. `LayoutEngine` updated to store
the mapping data. 3 new tests added (PopulatesOldToNewGid, SortedGidsAreAscending,
SubsetBytesUnchanged); all 8 TrueTypeFontSubsetter tests pass.

**Files:** `TrueTypeFontSubsetter.cs`, `EmbeddedFontInfo.cs`, `LayoutEngine.cs`,
`TrueTypeFontSubsetterTests.cs`

---

### Plan 02 — CID Type0 / CIDFontType2 / FontDescriptor / FontFile2 + ToUnicode CMap (COMPLETE)

**Result:** Green. `OwnedPdfWriter` now emits the full 5-object CID font structure per face:
Type0, CIDFontType2, FontDescriptor, FontFile2 (FlateDecode), ToUnicode CMap. Content streams
encode text as 2-byte big-endian GID hex strings (`<GGGG>`) via a composed cp→newGid map.
Vietnamese text renders correctly (no `?` substitution). `OldToNewGid` from Plan 01 is consumed
without any redundant cmap re-parse.

**SEC-02:** 0 occurrences of `/JavaScript`, `/Launch`, `/OpenAction`, `/EmbeddedFile` in
emitted PDF content (2 hits are both in source comments only).

**Files:** `OwnedPdfWriter.cs`, `OwnedPdfWriterCidFontTests.cs`

---

### Plan 03 — FlateDecode Compression + Stable Resource Ordering (COMPLETE)

**Result:** Green. All content streams and FontFile2 streams are FlateDecode-compressed using
`System.IO.Compression.ZLibStream` (RFC 1950 wrapper, not `DeflateStream`). `/Length1`
emitted for FontFile2 per PDF 1.7 §9.9.3. Font resource tracking replaced with
`List<(string ResourceName, FontObjectIds Ids, EmbeddedFontInfo Info)>` for stable /F0, /F1, ...
assignment. Output PDF size for a text-only page: ~24 KB (was ~2.67 MB in spike).

**Files:** `OwnedPdfWriter.cs`, `OwnedPdfWriterCompressionTests.cs`

---

### Plan 04 — Image XObjects (JPEG /DCTDecode + PNG raw-RGB /FlateDecode) (COMPLETE)

**Result:** Green. `ReplacedBox` elements now handled in content streams.
- JPEG: raw bytes passthrough as `/DCTDecode` XObject (zero re-encoding allocation)
- PNG (8-bit RGB only): IDAT chunks concatenated, inflated with `ZLibStream` (RFC 1950,
  not `DeflateStream`), all 5 PNG filter types un-filtered, re-compressed with FlateDecode
- Unsupported PNG variants (RGBA, 16-bit, palette) throw `PdfFormatException`
- Y-coordinate correctly flipped: `pdfY = pageHeight - el.Y - el.Height`
- Image list uses `List<(string ResourceName, int ObjectId, string Src)>` for stable ordering

**Key correction applied:** PNG IDAT is RFC 1950 (zlib-wrapped). `ZLibStream` used, not
`DeflateStream`, per `08.5-RESEARCH-VERIFY.md` items #2/#3.

**Files:** `OwnedPdfWriter.cs`, `OwnedPdfWriterImageTests.cs`

## Deviations

1. **Plans 02/03/04 committed as a single atomic commit.** The three plans are deeply
   interdependent in `OwnedPdfWriter.cs` (FlateDecode is needed for FontFile2 which is part
   of Plan 02; image XObjects in Plan 04 need the compression helper from Plan 03). Writing
   them sequentially with intermediate broken-build states would have been artificial.
   All success criteria for each plan are met.

2. **56 golden files updated, not 57.** The Golden/ directory contained 56 files, not 57.
   All existing baselines were re-generated successfully.

3. **qpdf validation skipped.** `qpdf` is not installed on this host. Structural PDF validity
   is instead confirmed by the determinism canary (renders each case twice, asserts byte-identity,
   which requires the PDF to be parseable and reproducible) and by the test suite passing.

4. **SC4 per-stage numbers not captured in test output.** `ITestOutputHelper` output is not
   piped to the console in the CI-equivalent run mode used here. The assertion
   (`totalMb.Should().BeLessThanOrEqualTo(Sc4ThresholdMb)`) passes, confirming SC4 is met.
