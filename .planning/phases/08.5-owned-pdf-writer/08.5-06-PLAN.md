## Why DisableParallelization can be removed now

From the PdfRenderCollection.cs comment (per RESEARCH.md): "PdfSharpCore keeps process-global mutable font state... Assigning all renderers to one non-parallel collection removes the race deterministically." With OwnedPdfWriter as the registered writer, PdfSharpCore's GlobalFontSettings.FontResolver is no longer set. No global state race exists. Parallelism is safe.

## What to expect after the swap

- Golden snapshot tests (all 57) will likely fail on byte-equality — OwnedPdfWriter produces structurally different bytes from PdfSharpCoreWriter. This is EXPECTED. Do not treat golden failures as blockers here; they are addressed in Plan 07.
- DeterminismCanaryTests will now run against OwnedPdfWriter via DI and should pass (same input → same output), even though baselines differ.
- All non-golden integration tests should pass.
