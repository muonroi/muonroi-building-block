  <behavior>
    - Cascade order: for an element matched by `.a { color: red }` (spec 10) and `#x { color: blue }`
      (spec 10000), resolved color == blue (higher specificity wins).
    - !important: `.a { color: red !important }` beats `#x { color: blue }` despite lower specificity.
    - Source order tiebreak: two `.a { color: ... }` rules with equal specificity → the later one wins.
    - Inline overlay: element with `style="color: green"` beats a matched `.a { color: red }` author rule.
    - Shorthand: `border: 1px solid red` → border-top/right/bottom/left-width = 1px (+ style/color longhands).
    - Shorthand 2-value: `padding: 2px 6px` → padding-top/bottom = 2px, padding-left/right = 6px (G27).
    - UA default: a `th` with no author font-weight resolves font-weight: bold AND text-align: center;
      a `td` does NOT get bold. h1-h6 resolve bold. `b/strong` bold, `i/em` italic, `u` underline.
    - UA display map: table/thead/tbody/tfoot/tr/td/th/caption resolve their HTML5 display values
      (table, table-row-group, table-row, table-cell, table-caption) when no author display is set.
    - Inheritance: parent color: red, child with no own color → child resolved color == red. A
      non-inherited property (e.g. border-top-width) does NOT inherit.
    - Units: font-size 16px context, `padding: 1em` → padding longhands resolve to 16px (em→px).
      `width: 50%` → resolved value stays the literal string "50%". `border-top-width: 1px` → "1px".
    - Descendant G25: `.t td { border: 1px solid }` + `.t tr.no-border td { border: none }` on a
      td inside `tr.no-border` → border-*-width resolves to 0/none (suppressed); a td in a plain tr keeps 1px.
    - G28: `.t td { word-break: break-word }` matches a `td class="text-center"` inside `table class="t"`
      (own class differs) → word-break resolves to break-word.
    - G29: `.t td { white-space: nowrap }` resolves white-space: nowrap on the cell AND (being inherited)
      the resolved map is available for inline children to inherit.
  </behavior>
  <action>
    Create `OwnedComputedStyle.cs`: `internal sealed class OwnedComputedStyle : IComputedStyle` wrapping a
    `Dictionary&lt;string,string&gt;` (case-insensitive keys). `GetValue(p)` returns the entry or null;
    `HasProperty(p)` returns non-empty presence. Mirror the shape of `AngleSharpComputedStyle` (which it
    will replace at the seam in Plan 03). No `ICssStyleDeclaration` dependency.

    Create `CascadeResolver.cs`: `internal sealed class CascadeResolver` constructed with a `CssRuleSet`.
    Method `internal Dictionary&lt;string,string&gt; Resolve(IElement element, IReadOnlyDictionary&lt;string,string&gt;? parentResolved)`
    implementing DESIGN §4.2 in order:
    1. Match: `ruleSet.Rules.Where(r => element.Matches(r.SelectorText))` (AngleSharp CORE — never throws).
       Guard each Matches in case AngleSharp rejects an exotic selector: catch the specific selector-parse
       exception, LOG it with the selector text and continue (No-Silent-Catch — log, do not swallow blind).
    2. Sort matched ascending by (Important, Specificity, SourceOrder); apply declarations into the map,
       last-wins. Keep important and non-important as distinct tiers (all important after all non-important).
    3. Inline overlay: read `element.GetAttribute("style")`; split into k:v declarations; apply non-important
       inline on top of the non-important author tier, inline-important at the very top.
    4. Shorthand expansion (table-driven, bounded set): `border`, `border-{top|right|bottom|left}`,
       `margin`, `padding`, `background`, `font`, `text-decoration`. Expand to the longhands BoxTreeBuilder
       reads (e.g. border → border-*-width/-style/-color; margin/padding → 4 sides with 1/2/3/4-value CSS
       rules; `border: none`/`0` → width 0). Mirror the existing shorthand semantics in BoxTreeBuilder
       (read_first) so golden output stays byte-identical for simple docs.
    5. UA defaults layer (apply ONLY where the property is still unset — lowest precedence): HTML5 display
       map for table structural elements; `th` → font-weight: bold + text-align: center; `h1`–`h6` →
       font-weight: bold; `b`/`strong` → font-weight: bold; `i`/`em` → font-style: italic; `u` →
       text-decoration: underline; `hr`. Reuse the exact tag→value mappings already in BoxTreeBuilder.
    6. Inheritance: for each property in the inherited allow-list (color, font-family, font-size,
       font-weight, font-style, line-height, text-align, text-transform, white-space, word-break,
       overflow-wrap, word-wrap, visibility, list-style*) that is unset after steps 1-5, copy from
       `parentResolved`. Keep the allow-list as a `static readonly HashSet&lt;string&gt;`.
    7. Unit resolution: resolve the element's effective font-size first (inherited or own, default root
       16px), then convert em/rem values on length properties to px using that font-size (rem against the
       root 16px). Leave `%` values as literal strings. Leave px/pt/mm/cm untouched (downstream normalizes).
       Reuse/centralize the em handling logic equivalent to BoxTreeBuilder.ParseLength's em branch.

    Do NOT call `IWindow.GetComputedStyle` / `ComputeCurrentStyle` anywhere. Do NOT modify Abstractions,
    BoxTreeBuilder, or any layout file. Every catch logs module + selector/property + message (No-Silent-Catch).
