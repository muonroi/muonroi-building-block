<objective>
Build `CssRuleSet` — the document-level CSS rule index that the owned cascade resolves against. It
collects every author style rule from `document.StyleSheets` once, splits grouped selectors into
individual entries, records specificity + source order, and exposes each declaration (property,
value, `!important`) read from `ICssStyleRule.Style`.

Purpose: this is the contract every later plan consumes. The `CascadeResolver` (Plan 02) matches
elements against these entries; the `OwnedStyledNode` (Plan 03) holds one shared `CssRuleSet` per
document. Defining and unit-testing it first means downstream plans receive a stable, tested
interface instead of exploring the CSSOM themselves.

Output: `CssRuleSet.cs` + `CssRuleSetTests.cs`. No wiring to the seam yet (Plan 03 does that).
</objective>

```csharp
using AngleSharp.Css.Dom;
using AngleSharp.Dom;

foreach (ICssStyleSheet sheet in document.StyleSheets.OfType<ICssStyleSheet>())
{
    ICssRuleList rules = sheet.Rules;
    for (int i = 0; i < rules.Length; i++)
    {
        if (rules[i] is ICssStyleRule styleRule)
        {
            string selectorText = styleRule.SelectorText;        // e.g. ".t th, .t td"
            ICssStyleDeclaration? decls = styleRule.Style;        // declaration block
            // per declaration: decls.GetPropertyValue(name), decls.GetPropertyPriority(name) == "important"
            // enumerate declared property names: iterate decls (it is IEnumerable<string> of property names)
        }
        // element.Matches(styleRule.SelectorText) is used at resolve time (Plan 02), NOT here.
    }
}
```

  <behavior>
    - Given a parsed document with `&lt;style&gt;.a { color: red }&lt;/style&gt;`, CssRuleSet.FromDocument
      produces ONE entry: selectorText ".a", one declaration { property "color", value "red", Important false }.
    - Given `.a, .b { color: red }`, produces TWO entries (one per split simple selector), each with
      the same declaration set, each with its own specificity.
    - Given `.a { color: red !important }`, the declaration's Important flag is true.
    - Source order increments across rules in document order (rule appearing later has a higher sourceOrder).
    - Only ICssStyleRule entries are collected; @page / @font-face / @import / @keyframes are ignored.
  </behavior>
  <action>
    Create internal sealed types in `Muonroi.Pdf.Governance.Cascade`:
    a record `CssDeclaration(string Property, string Value, bool Important)` — Property is lowercased;
    a record `CssMatchableRule(string SelectorText, int Specificity, int SourceOrder, IReadOnlyList&lt;CssDeclaration&gt; Declarations)`;
    and `internal sealed class CssRuleSet` holding `IReadOnlyList&lt;CssMatchableRule&gt; Rules`.

    Add `internal static CssRuleSet FromDocument(IDocument document)`:
    1. Iterate `document.StyleSheets.OfType&lt;ICssStyleSheet&gt;()` then `sheet.Rules` (see &lt;read_first&gt; for the exact
       loop). For each `ICssStyleRule`, read declarations from `styleRule.Style`: enumerate the declaration
       block's property names, and for each capture `GetPropertyValue(name)` and
       `GetPropertyPriority(name) == "important"`. Lowercase the property name. Skip empty values.
    2. Split the grouped `styleRule.SelectorText` on top-level commas into individual simple-selector strings
       (trim each). Emit one CssMatchableRule per split selector, all sharing the same declaration list.
    3. Specificity: compute it for the SPLIT (individual) selector. Prefer AngleSharp's parsed
       `styleRule.Selector` / `ISelector.Specificity` when it corresponds to a single split selector;
       when the rule was grouped, fall back to a manual specificity computation per CSS 2.1 §6.4.3
       (a = #id count, b = .class/[attr]/:pseudo-class count, c = element/::pseudo-element count;
       pack as `a*10000 + b*100 + c`). Document which path is taken in a code comment.
    4. SourceOrder: a single monotonically increasing counter advanced once per emitted entry, in
       document iteration order (sheet order, then rule order, then split order).

    Do NOT call `element.Matches` here (that is resolve-time, Plan 02). Do NOT swallow exceptions —
    if `GetPropertyValue` throws, let it surface (No-Silent-Catch rule); selector matching is what
    threw before, and that is not invoked here.
    Use GlobalUsings already present in the Governance project for AngleSharp namespaces where available;
    add explicit `using AngleSharp.Css.Dom;` / `using AngleSharp.Dom;` if not.
  </action>
