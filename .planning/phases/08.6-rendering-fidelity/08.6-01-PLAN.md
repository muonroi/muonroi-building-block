<objective>
Harden the font subsetter and image decoder with explicit fail-loud rejection for unsupported input formats. OTF-CFF fonts currently pass through silently and corrupt Vietnamese/Unicode output via a Latin-1 fallback; this fixes that by throwing. WOFF/WOFF2 already throws but with a generic message; this adds an explicit error code. PNG variant validation is moved from the writer layer to the decoder boundary so callers receive a structured error at the public seam.

Purpose: Closes the three worst silent-failure paths (FIDELITY-08, 09, 10, 11) before any layout work touches these data paths. Low risk, high safety value — the fixes are targeted single-method changes.
Output: TrueTypeFontSubsetter.cs and PureImageDecoder.cs with explicit rejection gates; full build green.

## TrueTypeFontSubsetter current state (lines 28-35, from RESEARCH.md)

The method opens with `uint sfntVersion = ReadUInt32BE(fontBytes, 0)` then:

```csharp
// Lines 28-31 — SILENT CORRUPTION BUG — must become a throw
if (sfntVersion == SfntVersionCFF)          // 0x4F54544F
    return new FontSubsetResult(fontBytes, new Dictionary<ushort, ushort>(), Array.Empty<ushort>());

// Lines 33-35 — already throws, but generic message
if (sfntVersion != SfntVersionTTF)
    throw new PdfFormatException("FONT-FORMAT",
        $"Unrecognized font format (sfntVersion: 0x{sfntVersion:X8})");
```

The fix:
1. Add two constants above the CFF check:
   `const uint SfntVersionWOFF  = 0x774F4646u;`
   `const uint SfntVersionWOFF2 = 0x774F4632u;`

2. Replace the CFF `return` (lines 28-31) with:
   `throw new PdfFormatException("FONT-OTF-CFF", "OTF font with CFF/PostScript outlines (sfntVersion=0x4F54544F) is not supported. Convert the font to TrueType outlines (.ttf with sfntVersion=0x00010000) before embedding, or use a TTF variant of the same typeface.");`

3. Add explicit WOFF/WOFF2 detection BEFORE the generic throw (lines 33-35):
   ```csharp
   if (sfntVersion == SfntVersionWOFF || sfntVersion == SfntVersionWOFF2)
       throw new PdfFormatException("FONT-WOFF",
           "WOFF/WOFF2 web fonts are not supported. Convert to a TrueType (.ttf) font before embedding.");
   ```
   The existing generic throw on line 33-35 remains as the final fallback for truly unknown formats.

`PdfFormatException` constructor: `(string errorCode, string message)` — confirmed in `src/Muonroi.Pdf.Abstractions/Exceptions/PdfFormatException.cs`.

## PureImageDecoder.DecodePng current state (from RESEARCH.md)

`DecodePng(byte[] data)` reads IHDR width (offset 16) and height (offset 20) but does NOT read bit_depth (offset 24) or color_type (offset 25). Insert the following validation block immediately after reading width/height, before constructing `DecodedImage`:

```csharp
byte bitDepth  = data[24];
byte colorType = data[25];

if (colorType == 3)
    throw new PdfFormatException("PNG-PALETTE",
        "Palette/indexed PNG (color_type=3) is not supported. Convert to 8-bit RGB PNG.");
if (colorType == 0)
    throw new PdfFormatException("PNG-GRAYSCALE",
        "Grayscale PNG (color_type=0) is not supported. Convert to 8-bit RGB PNG.");
if (colorType == 4)
    throw new PdfFormatException("PNG-GRAYSCALE-ALPHA",
        "Grayscale+alpha PNG (color_type=4) is not supported. Convert to 8-bit RGB PNG.");
if (colorType == 6)
    throw new PdfFormatException("PNG-RGBA",
        "RGBA PNG (color_type=6) is not supported. Convert to 8-bit RGB PNG (strip alpha channel).");
if (colorType == 2 && bitDepth == 16)
    throw new PdfFormatException("PNG-16BIT",
        "16-bit RGB PNG (bit_depth=16) is not supported. Convert to 8-bit RGB PNG.");
if (colorType != 2 || bitDepth != 8)
    throw new PdfFormatException("PNG-FORMAT",
        $"Unsupported PNG: color_type={colorType}, bit_depth={bitDepth}. Only 8-bit RGB (color_type=2, bit_depth=8) is supported.");
```

The writer's existing check in `OwnedPdfWriter.DecodePngToRawRgb` is retained as a defensive second gate — do not remove it.
