## BT/ET wrapping rule (RESEARCH.md Pitfall 1)

PDF path operators (`re f`) are INVALID inside a BT/ET text block. The established pattern in OwnedPdfWriter (used for image embedding, lines 588-607) is:
```
ET             % close text block
q              % save graphics state
<color> rg     % set fill color
<x> <y> <w> <h> re   % rectangle path
f              % fill
Q              % restore graphics state
BT             % reopen text block
```
Use this same pattern for text-decoration and <hr> drawing.

## text-decoration drawing (RESEARCH.md §1C)

FontSize-based estimation (Option B — sufficient for Phase 8.6):
- **Underline:** y (PDF coords) = `textBaselineY - (fontSize × 0.1)`, thickness = `fontSize × 0.07`
- **Strikethrough:** y (PDF coords) = `textBaselineY + (fontSize × 0.35)`, thickness = `fontSize × 0.07`
- x-span: from left edge of the word to right edge (wordX to wordX + wordWidth)
- Color: same RGB values as the text run's color (inline.Color, already parsed for the Tj emission)

PDF baseline Y: the writer already computes `float baselineY = pageHeightPt - el.Position.Y` (Y=0 at bottom of page, layout Y=0 at top). Underline drops below baseline (subtract), strikethrough is above baseline (add).

After emitting the `Tj` operator for a text run where `inline.TextDecoration` is "underline" or "line-through":
```
ET
q
<r> <g> <b> rg
<x> <y_dec> <w> <thickness> re
f
Q
BT
/F0 <size> Tf    % must restate font after BT
```
Note: after closing and reopening BT, the font/size state is lost and must be restated before the next glyph run.

## <hr> drawing (RESEARCH.md §2B)

When `PositionedElement.Source is HrBox hr`:
- Close ET, emit the rectangle, reopen BT.
- PDF coords: `y = pageHeightPt - el.Position.Y - el.Position.Height / 2f` (center of the reserved space).
- Width: `el.Position.Width` (full content width — set by BlockLayoutEngine).
- Thickness: `hr.Thickness` (default 1pt).
- Color: `hr.Color ?? "0.5 0.5 0.5"` — parse as three float values "r g b".
- The HrBox PositionedElement has no text — no Tj emission needed; just the path operators.

## /Annots link annotations (RESEARCH.md §2D + PDF notes)

### Object ID reservation

After reserving content stream + font/image object IDs for a page, reserve one additional object ID per annotation in `PositionedPage.LinkAnnotations`:
```csharp
int[] annotIds = page.LinkAnnotations
    .Select(_ => store.ReserveId())
    .ToArray();
```

### Page dict

When emitting the page dict (`/Type /Page /Parent ... /Contents ... /Resources ...`), if `annotIds.Length > 0`:
```
/Annots [ N1 0 R N2 0 R ... ]
```
where N1, N2, ... are the reserved annotation object IDs.

### Annotation objects

After the page's content stream object, emit each annotation as an indirect PDF object:
```
N1 0 obj
<< /Type /Annot
   /Subtype /Link
   /Rect [llx lly urx ury]
   /Border [0 0 0]
   /A << /S /URI /URI (https://example.com) >>
>>
endobj
```

Rect coordinate transform (RESEARCH.md Pitfall 4 — Y flip):
```csharp
float llx = annot.X;
float lly = pageHeightPt - annot.Y - annot.Height;
float urx = annot.X + annot.Width;
float ury = pageHeightPt - annot.Y;
```
