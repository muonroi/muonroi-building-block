## DefaultStrictPolicy structure (from RESEARCH.md)

`DefaultStrictPolicy` implements `IPdfCssPolicy`. Its `CheckCssFeatures` method runs in multiple passes:
- Pass 1: CSS property block violations (display:flex, float, position:absolute, etc.)
- Pass 2: CSS value violations
- Pass 3 (to be added): HTML element security — check element attributes for dangerous content

The policy takes an `IHtmlDocumentContext` (or `IParsedDocument`) that provides access to the DOM. It already has precedent for element-level checks (the `<script>` tag rejection lives in this class).

## New Pass 3 check to add

After the existing element checks (e.g., `<script>` rejection), add a scan for `<a>` elements:

```csharp
// Pass 3: dangerous href schemes
foreach (var anchor in document.QuerySelectorAll("a[href]"))
{
    var href = anchor.GetAttribute("href") ?? "";
    string scheme = "";
    if (Uri.TryCreate(href, UriKind.Absolute, out var uri))
        scheme = uri.Scheme;

    bool allowed = scheme is "" or "http" or "https" or "mailto";
    // empty scheme = relative URL = allowed
    if (!allowed)
    {
        violations.Add(new PolicyViolation(
            "forbidden.link.scheme",
            $"<a> href scheme '{scheme}' is not allowed. Only http, https, and mailto URIs are permitted as link annotations.",
            href,
            "Use an http or https URI."));
    }
}
```

`PolicyViolation` constructor: `(string featureName, string message, string value, string suggestion)` — confirm from `src/Muonroi.Pdf.Abstractions/Policy/PolicyViolation.cs`.

`document.QuerySelectorAll` is available on the `IHtmlDocumentContext` or the underlying AngleSharp DOM — check how the existing `<script>` rejection iterates elements and use the same pattern.
