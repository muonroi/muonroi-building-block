## Dockerfile pattern (from RESEARCH.md Pattern — Alpine multi-stage)

```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0-alpine AS build
WORKDIR /src
RUN apk add clang build-base zlib-dev
COPY . .
RUN dotnet publish samples/Muonroi.Pdf.AotSample/Muonroi.Pdf.AotSample.csproj \
    -r linux-musl-x64 \
    -c Release \
    --self-contained \
    -o /app/publish \
    -m:1 -nodereuse:false

FROM mcr.microsoft.com/dotnet/runtime-deps:8.0-alpine AS runtime
WORKDIR /app
COPY --from=build /app/publish .
ENTRYPOINT ["/app/Muonroi.Pdf.AotSample"]
```

Note: The `COPY . .` copies the entire repo. This works because `dotnet publish` runs from `/src` with the project path. Alternatively, use selective COPY to reduce build context size.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Docker build context → SDK container | Full repo is COPY'd into Docker build context; no secrets in repo root; build context is local only |
| ArrayPool<T> reuse → render isolation | Pooled buffers must be cleared or length-tracked before reuse to prevent cross-render data leakage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-F-01 | Information Disclosure | ArrayPool<T> reuse | mitigate | When renting from ArrayPool, use the `clearArray: true` flag on Return, OR use the length-bounded slice pattern (never expose rented array beyond its valid length). Prevents stale bytes from prior renders appearing in output. |
| T-08-F-02 | Denial of Service | Docker build consuming disk | accept | Alpine multi-stage image; runtime stage copies only publish output; build artifacts discarded. Image size gate enforces compactness. |
| T-08-F-SC | Tampering | NuGet package installs | accept | No new NuGet packages in this plan; optimizations use BCL ArrayPool/Span only |
</threat_model>
