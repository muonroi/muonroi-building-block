## AOT strategy (from decisions + RESEARCH.md)

Primary: `PublishAot=true`. If AngleSharp.Css reflection breaks at RUNTIME (binary exits non-zero on golden corpus render), fall back to `PublishTrimmed=true` and record as accepted deviation in 08-04-SUMMARY.md.

The trim warnings from AngleSharp.Css (IL2026/IL2055/IL3050) are EXPECTED — do not treat them as failures. The TrimmerRootDescriptor `preserve="all"` is the mitigation: it keeps the types AngleSharp needs at runtime even though the linker cannot statically verify they are used.

## Confirmed reflection call sites OUT OF SCOPE

- `Muonroi.Observability/OtelSetup.cs` lines 45-49: `AppDomain.CurrentDomain.GetAssemblies()` + `Activator.CreateInstance` — NOT in Pdf packages; AOT sample must not reference this assembly.
- `ITenantContextPolicy.cs` line 103: `AppDomain.CurrentDomain.GetAssemblies()` — NOT in Pdf packages.

## Engine hot path: no reflection found

Per RESEARCH.md: `MPdfService`, layout engine, writer use no `Activator.CreateInstance`. Hot path is already reflection-free. The annotation task is:
1. Grep `src/Muonroi.Pdf/` and `src/Muonroi.Pdf.Governance/` for `GetType()`, `typeof(`, `Type.GetProperties`, `Type.GetMethods`, `Activator.`, `Assembly.` — annotate or document any found instances.
2. If `IHtmlParser`, `ICssCascadeEngine` adapter types use `typeof(T)` for generic registration, add `[DynamicallyAccessedMembers(DynamicallyAccessedMemberTypes.PublicConstructors)]` to the type parameter constraint or the registration call.
3. If nothing is found (engine is already clean), add a comment block in `Muonroi.Pdf.csproj` noting AOT-01 verified clean.

## Golden corpus for AOT-02

The AOT sample Program.cs should:
1. Construct minimal DI (no Observability, no Tenancy)
2. Render a small known-good HTML string (50-100 bytes is sufficient for smoke test)
3. Write output to a temp file or /tmp/aot-sample-output.pdf
4. Print byte count to stdout
5. Exit 0 on success, non-zero on exception

The golden corpus comparison in AOT-02 is: if the byte count > 0 and no exception, the render path functions under AOT. Byte-identical comparison with the JIT path is aspirational — it requires running both under identical GC/RNG state which is not practical in a console sample. Accept "renders non-empty PDF without exception" as the AOT-02 verification.

```csharp
// samples/Muonroi.Pdf.AotSample/Program.cs
using Microsoft.Extensions.DependencyInjection;
using Microsoft.Extensions.Configuration;
using Muonroi.Pdf.Abstractions;

var config = new ConfigurationBuilder().Build();
var services = new ServiceCollection();
services.AddPdf(config);
var provider = services.BuildServiceProvider();
var pdfService = provider.GetRequiredService<IMPdfService>();

const string html = "<!DOCTYPE html><html><body><h1>AOT Sample</h1><p>Hello from NativeAOT.</p></body></html>";
using var output = File.OpenWrite(args.Length > 0 ? args[0] : "/tmp/aot-sample-output.pdf");
var result = await pdfService.RenderAsync(html, output, new Muonroi.Pdf.Abstractions.PdfRenderOptions());
Console.WriteLine($"AOT render OK: {result.PageCount} page(s), {result.ByteCount} bytes");
```

| Boundary | Description |
|----------|-------------|
| AOT binary → filesystem | AOT sample writes PDF to /tmp; no network access; ThrowingResourceResolver default still applies |
| TrimmerRootDescriptor → AngleSharp internals | preserve="all" keeps all AngleSharp types; this is intentionally broad to prevent runtime failures; no security impact as AngleSharp processes HTML we supply |
