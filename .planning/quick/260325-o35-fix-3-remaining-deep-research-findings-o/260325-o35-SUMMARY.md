## Changes Made

### Task 1: RLS SQL Script Fix

**File:** `muonroi-building-block/db/migrations/0001_enable_rls_postgres.sql`

- Changed `current_setting('app.current_tenant')::uuid` to `current_setting('app.current_tenant_id', true)`
- Setting name `app.current_tenant` -> `app.current_tenant_id` (matches `TenantRlsConnectionInterceptor`)
- Removed `::uuid` cast — TenantId is a string type, the cast caused silent RLS failures for non-UUID tenant IDs
- Added second argument `true` so `current_setting()` returns NULL instead of throwing when not set
- Added `FORCE ROW LEVEL SECURITY` after `ENABLE ROW LEVEL SECURITY` — ensures policy applies to table owner too

### Task 2: Viewer Policy Fix

**File:** `muonroi-control-plane/src/Muonroi.ControlPlane.Api/Endpoints/ControlPlanePolicies.cs`

- Added `"cp.viewer"` to the Viewer policy's `HasPermission` call
- Before: only `cp.admin` and `cp.approver` were accepted — users with `cp.viewer` got 403 on viewer endpoints
- After: policy accepts `cp.admin`, `cp.approver`, and `cp.viewer` — correct hierarchy enforced

### Task 3: Connector Persistence

**Files:** `Muonroi.ControlPlane.Api.csproj`, `Program.cs`

- Added `<ProjectReference>` to `Muonroi.Integration.Persistence` in csproj (alongside existing Integration.Abstractions and Integration.Connectors refs)
- Replaced `AddSingleton<IConnectorConfigStore, InMemoryConnectorConfigStore>()` and `AddSingleton<IConnectorCredentialStore, InMemoryConnectorCredentialStore>()` with `AddMConnectorPersistence(connectionString)`
- `AddMConnectorPersistence` registers `ConnectorDbContext` + `EfConnectorConfigStore` + `EfConnectorCredentialStore` as Scoped services
- Connector config and credentials now persist across Control Plane restarts via Postgres
